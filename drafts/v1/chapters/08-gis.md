# 地理信息：坐标与图层的秩序

!!! abstract "本章要点"
    GIS 和 CAD 看起来都是“在画布上画东西”，但 GIS 多了一套坐标系和一套属性表。这两样东西决定了它的数据模型、渲染方式和交互逻辑。QGIS 是理解这套体系的最好样本，GPXSee 则展示了小团队如何用 Qt 做出一个完整的专业工具。

## 8.1 坐标系是第一公民

CAD 里的坐标是笛卡尔的，单位是毫米，原点随便定。GIS 里的坐标必须对应地球上的一个位置，于是有了坐标参考系（CRS）。

一个点可以用经纬度表示（WGS84），也可以投影到平面上（Web Mercator、UTM、高斯克吕格）。不同 CRS 之间要转换，转换有精度损失，也有适用范围。GIS 软件的第一个基本功，就是让所有数据在同一个 CRS 下对齐显示，同时保留原始坐标不被破坏。

这件事的工程含义是：**每个图层都带着自己的 CRS，渲染时实时重投影。** 如果设计成“打开时统一转成一种坐标”，数据一进一出就会变形；如果设计成“每次绘制都转”，性能又受不了。QGIS 的做法是引入一层坐标变换缓存，按图层缓存变换后的几何。

第二套东西是属性表。CAD 的实体只有几何，GIS 的要素是“几何 + 属性”。一条道路既有折线，也有等级、宽度、限速、建成时间。这决定了 GIS 的数据模型必须是“要素类”而不是“图元列表”，也决定了它的界面必须有属性表、符号化、查询。

## 8.2 QGIS 的分层

QGIS 是开源 GIS 的旗舰，GPLv2，Qt 写成，社区巨大。

它的代码分层很清晰：

- `core`：图层、要素、坐标系、渲染接口、表达式引擎。不依赖界面。
- `gui`：地图画布、图层树、符号化对话框、属性表。
- `app`：主程序、菜单、插件宿主。
- `python`：PyQGIS 绑定。
- `plugins`：官方与第三方插件。

这个分层带来两个好处。第一，PyQGIS 可以在无界面环境下跑批处理，服务器端做空间分析很常见。第二，插件可以只依赖 `core` 和 `gui`，不必碰主程序。

QGIS 的渲染是一个值得研究的点：图层（layer）→ 符号（symbol）→ 渲染器（renderer）→ 缓存（cache）。地图缩放时，只有可见范围、可见比例尺的图层参与绘制；重绘时按图层缓存，避免每次全量重算。

## 8.3 插件与处理框架

QGIS 的插件生态是它成功的关键。插件用 C++ 或 Python 写，注册到菜单、工具栏、处理工具箱。Python 插件不需要编译，分发成本极低。

处理框架（Processing）更进了一步：它把算法抽象成“输入参数 → 执行 → 输出结果”，算法可以来自 QGIS 本身、GDAL、GRASS、SAGA，也可以是用户用 Python 写的脚本。用户在图形界面里搭工作流，导出成模型，或者直接用命令行跑。

这套设计的启示是：**把“算法”和“界面”彻底分开，算法只描述参数和结果，界面自动生成。** 对工业软件同样适用：一个求解器、一个网格算法、一个数据处理步骤，都可以用这种方式接入，而不必为每个算法写一个对话框。

## 8.4 GPXSee：小而完整

GPXSee 是一个 GPS 轨迹查看器，Qt 写成，GPLv3，作者基本是一个人维护。

它支持 GPX、TCX、KML、FIT、NMEA 等十几种格式，能加载在线和离线地图，显示速度、海拔、心率曲线，导出图片。代码量不大，但功能闭环完整，是“一个人如何用 Qt 做出专业工具”的样本。

它的价值在于**边界控制**：不追求做 GIS 平台，只做“看轨迹”这一件事，把这件事做到没有明显短板。地图瓦片、投影变换、轨迹简化、图表联动，每个模块都不复杂，但组合起来就是一个能日常使用的软件。

## 8.5 给做空间数据的人

三句话。

**坐标系不要自己做。** 用 PROJ，用 GDAL，用现成的库。投影变换的坑比几何内核还深，自己实现一定会错。

**图层是组织单位，不是绘制单位。** 数据量大时，渲染要按瓦片、按范围、按比例尺裁剪。全量绘制的代码在演示时很好看，在现场会卡死。

**属性查询要用索引。** 空间索引（R 树）加属性索引，是 GIS 能交互的前提。没有索引的“框选”，在十万要素上要几秒钟。
